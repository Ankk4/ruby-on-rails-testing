Use these as hard design rules for the project management UI:
- Optimistic, not nostalgic. It should feel like the future as imagined in 2002–2006, not like a retro parody.
- Bright by default. Base surfaces are pearl white, ice blue, pale silver, and soft cyan. Dark mode is not the primary expression.
- Chrome is an accent, not a background. Use metallic edges, trims, separators, and highlights sparingly.
- Glass must remain readable. Translucency is allowed only when contrast stays high; never put critical text over visually busy backgrounds.
- Blue is structural. Use blue/cyan for navigation, selection, active states, and system hierarchy.
- Lime is exceptional. Reserve lime/green for success, completion, and positive progress. Never use it decoratively everywhere.
- Gradients are mandatory but restrained. Prefer soft vertical or radial gradients with small value shifts. Avoid modern neon gradients.
- Shadows are soft and shallow. Surfaces should feel molded and layered, not floating several centimeters above the page.
- Corners are rounded, not bubbly. Use medium radii. Avoid pill-shaped everything.
- Every screen needs technical detail. Add small labels, timestamps, counters, progress markers, coordinates, IDs, or micro-status text where appropriate.
- Primary navigation should feel spatial. Projects, workstreams, and sections can behave like destinations or stations rather than plain database tabs.
- Favor maps, timelines, and dashboards over raw tables. Tables are secondary; the main experience should communicate movement, progress, and relationships.
- Use lines to show systems. Thin connectors, orbital paths, dependency lines, progress rails, and timeline guides are core motifs.
- One strong visual object per major view. A project orb, progress ring, timeline node, map hub, or large status graphic should anchor the composition.
- Icons should be dimensional. Use simple glossy, beveled, or semi-3D icons rather than flat monochrome SVGs everywhere.
- Typography should be technical but human. Futuristic display type is only for large headings; body copy stays highly readable.
- Uppercase micro-labels are encouraged. Use them for metadata and category labels, not long text.
- Information density can be high, but hierarchy must be obvious. Dense does not mean cramped.
- Animations should feel engineered. Use short fades, slides, soft scaling, and smooth orbital/line motion. No bouncy SaaS animation.
- Hover states should illuminate, not transform wildly. Slight glow, highlight, or surface lift is enough.
- Status colors must be semantic. Blue = active, green = complete, amber = risk, red = blocked/critical, gray = inactive.
- Avoid contemporary startup clichés. No giant purple blobs, no generic illustration people, no excessive gradient mesh, no flat card grid with identical tiles.
- Avoid cyberpunk. No black backgrounds, magenta neon, terminal rain, glitch effects, or dystopian visual noise.
- Avoid vaporwave. No irony, sunset grids, VHS noise, Greek statues, or lo-fi degradation.
- Avoid literal Frutiger Aero kitsch. No random grass, fish, bubbles, or water splashes unless they serve the product concept.
- The interface should feel expensive, calm, and precise.
- The future should feel useful. Every decorative element should reinforce navigation, state, progress, or system relationships.
For text specifically:
- Headings: short, confident, functional. Example: PROJECT CONTROL, TIMELINE, TEAM ACTIVITY, SYSTEM STATUS.
- Subheads: plain-language, optimistic, slightly aspirational.
- Buttons: verbs first. Create Project, Add Task, Open Timeline, View Progress.
- Avoid cute microcopy and startup slang.
- Prefer “In Progress”, “Complete”, “At Risk”, “Scheduled”, “Waiting” over playful labels.
- Use timestamps, percentages, counts, and dates prominently; the UI should feel instrumented.
- Keep empty states constructive: No active blockers., Timeline clear through Friday., 3 tasks ready to begin.
- Avoid exclamation marks except for genuine alerts.
- Tone should be calm, competent, and forward-looking.
The single sentence to judge every screen against is:
“Would this look believable in a 2005 vision of serious professional software from the near future?”
